 # AI ATLAS

## Production-Ready Product Requirements Document

**Product:** AI Atlas
**Product Type:** AI discovery, search, recommendation, comparison, workflow, and stack-building platform
**Primary Goal:** Help users find the right AI tools and build the right AI workflow based on what they actually want to accomplish.
**Product Principle:** **“Don’t search for AI tools. Tell us what you want to accomplish, and AI Atlas will find the right AI tools and build the right AI stack for you.”**

# 2. PRODUCT VISION

AI Atlas is not an AI tools directory.

It is a decision engine that connects:

**User → Goal → Intent → Capabilities → Tools → Workflow → Stack → Feedback**

The user should not need to know which AI tools exist.

The user should be able to say:

> “I want to launch a YouTube channel with AI, I am a beginner, and I have a ₹2,000 monthly budget.”

AI Atlas should understand the goal, identify the required capabilities, filter incompatible tools, rank suitable tools, explain why they were selected, and optionally construct a complete workflow.

The product's value is **decision quality**, not the number of tools listed. The underlying requirements explicitly prioritize reducing choices and identifying the strongest options rather than overwhelming users with thousands of listings.

Never create fake:

* Users
* Followers
* Reviews
* Ratings
* Tool statistics
* Tool pricing
* Recommendation results
* Search activity
* Analytics
* Verification status
* Admin actions
* Likes
* Comments
* Tool usage statistics

If real data does not exist:

* show a truthful empty state;
* use explicitly labelled demo/seed data only during development;

Never simulate a successful backend operation when nothing happened.

# 16. HARD CONSTRAINT ENGINE

Hard requirements must be filters.

Examples:

If:

> “Free only.”

Then a paid-only tool must be excluded.

If:

> “Must have an API.”

Then tools without an API must be excluded.

If:

> “Android only.”

Then unsupported tools must be excluded.

If:

> “Open source only.”

Then proprietary tools must be excluded.

Pipeline:

```text
Candidate Retrieval
        ↓
Hard Constraint Filtering
        ↓
Scoring
        ↓
Ranking
```

Do not let a higher score override a hard constraint.

---

# 17. RECOMMENDATION SCORING ENGINE

Use a transparent weighted scoring model.

Default weights:

| Factor           | Weight |
| ---------------- | -----: |
| Use-case match   |    35% |
| Capability match |    25% |
| Budget fit       |    15% |
| Quality          |    10% |
| Skill-level fit  |     5% |
| Reliability      |     5% |
| Platform fit     |     5% |

Normalize each component from `0–1`.

### IMPORTANT

The final score must be calculated as a **weighted sum**, not multiplication.

Correct model:

```ts
score =
  useCaseMatch * 0.35 +
  capabilityMatch * 0.25 +
  budgetFit * 0.15 +
  quality * 0.10 +
  skillFit * 0.05 +
  reliability * 0.05 +
  platformFit * 0.05;
```

Then:

```ts
finalScore = score * 100;
```

Store the weight configuration centrally in backend/system configuration.

Do not hardcode weights throughout UI components.

---

# 18. DYNAMIC WEIGHTING

Adapt weighting to user intent.

Example:

User:

> “I don't care about price. Give me the highest quality.”

Increase quality importance.

User:

> “I'm a student with no budget.”

Budget may become:

* Hard constraint
* Or extremely high-weight preference

depending on explicit wording.

User:

> “I want something extremely easy to use.”

Increase ease-of-use weight.

Create a configurable scoring system:

```ts
type RecommendationWeights = {
  useCase: number;
  capability: number;
  budget: number;
  quality: number;
  skill: number;
  reliability: number;
  platform: number;
  easeOfUse?: number;
};
```

# 20. AI EXPLANATION SYSTEM

After deterministic ranking, pass only the top candidates and verified database facts to the LLM.

The LLM should explain:

* Why the tool matches the goal
* Which requirements it satisfies
* Relevant strengths
* Relevant limitations

Example:

> Tool A is recommended because it matches your required video capabilities, supports your platform, fits your budget, and is suitable for beginners.

Then:

> However, its free plan has usage limits.

The LLM must not introduce facts absent from the supplied verified data.
